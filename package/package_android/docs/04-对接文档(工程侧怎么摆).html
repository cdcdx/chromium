1. 项目概述 & 架构

arupa-kernel.aar 是 Chromium 魔改内核的 Android 交付包（chromium 大版本以 docs/canonical-paths.md 顶部四标记为准，本文不抄），核心类 co.arupa.kernel.ChromiumWebView。不是 android.webkit.WebView 的子类，是 content_public.browser.WebContents 的薄 Java 封装，继承 FrameLayout。

双通道架构（必读）

内核对接面有两条互补通道，区分清楚再动手：

通道是什么适合场景NomadBrowser 实际用法
ChromiumWebView JNI（本文档主体）进程内 Java→JNI→native，同步View 实例化/渲染/生命周期、per-tab 代理身份、WebViewClient 等价回调setProxy、导航/对话框/认证/下载/find/状态序列化 等
CDP bridge（#217 NativeBridge over ADP）加密 socket 控制面，异步远程 agent 遥控：UA 覆盖、Cookie、请求拦截/改写、JS eval、截图远程场景保留；in-app 走 JNI 替代
选路口诀：

状态机 / 渲染 / 生命周期 / per-tab 代理身份 → JNI

远程 agent 遥控 / UA / Cookie / 网络拦截 / eval / 截图 → CDP

#231/#232/#233/#234/#235 已将 WebViewClient 全套 + UA/Cookie/拦截 JNI 化，in-app 脱离 CDP。CDP 仍是远程 agent 场景备用。

关键差异（迁移前必知）

  • 没有 WebViewClient/WebChromeClient，改用 ChromiumWebView.Client 接口（语义等价）。
  • Cookie/存储是 per-partition（每 View 实例独立 StoragePartition），不是全局 CookieManager。
  • 多了 setProxy/setTransportRoute/setPendingIdentity 等内核特权 API。
  • ⚠️ 禁忌：in-process chromium 内核与系统 android.webkit.WebView 不能同进程（JNI_OnLoad 时 SIGTRAP）。同一进程二选一。
  • 迁移建议：B 方案并行宿主（与 AOSP WebView 共存灰度切），不一次性替换所有 controller。

3. AAR 引入方式

将 arupa-kernel.aar 放置到 app/libs/ 目录，然后在 build.gradle 中引用：

// build.gradle (app)
repositories {
    flatDir { dirs("libs") }
}
dependencies {
    implementation(fileTree(dir: "libs", include: ["*.aar"]))
    // 或显式:
    // implementation(files("libs/arupa-kernel.aar"))
}

android {
    // 运行时资产不能压缩（必须，否则 ICU 初始化崩）
    androidResources {
        noCompress("dat", "bin", "pak", "apk")
    }
    // packaging 去重（见第 7 章）
    packaging {
        resources {
            excludes += listOf(
                "META-INF/*.kotlin_module",
                "META-INF/MANIFEST.MF",
                "META-INF/versions/**",
                "META-INF/*.proto",
                "DebugProbesKt.bin"
            )
        }
    }
}
⚠️ guava / jspecify 排除规则注意

AAR 内部 bundle 了 com.google.common / jspecify。若要排除，只排 compile/runtime，不排 annotationProcessor——全排会导致 AP NoClassDefFoundError com.google.common.collect.Sets。

VendorAuthn 授权

内核特权 API（setProxy/setTransportRoute/setPendingIdentity 等）需要 vendor 包名 + 证书授信。对接阶段内核侧会将你的包名加入 VendorAuthn.TRUSTED_VENDOR_IDS，重编 AAR 交付。生产环境切为 cert hash 验证。

未授信 vendor 调特权 API = 静默 no-op（不抛异常），若调用没生效先检查 VendorAuthn 配置。

开发机 com.example.kernelapp 已硬编为可信，可直接测试。

4. 初始化序列（生命周期）

🔴 子进程守卫必做

chromium 子进程（:sandboxed_processN / :privileged_processN）只做 ArupaKernel.loadNativeLib() 然后 return，不能走完整 initialize。AAR 不内嵌 NativeLibraries，子进程不自 load 会出 UnsatisfiedLinkError。

// ① Application.onCreate —— 主进程一次性初始化（放任何 Activity 之前）
class MyApplication : Application() {
    override fun onCreate() {
        super.onCreate()
        if (isMainProcess()) {
            // 主进程：完整初始化（加载 libarupakernel.so + 资源）
            ArupaKernel.initialize(this)
        } else {
            // chromium 子进程：只加载 native lib，其余跳过
            ArupaKernel.loadNativeLib()
            return
        }
        // 主进程后续初始化...
    }

    private fun isMainProcess(): Boolean {
        // 读 /proc/self/cmdline，首段 == packageName = 主进程
        val cmdline = File("/proc/self/cmdline").readText().trim('\0')
        return cmdline == packageName
    }
}

// ② 每个 WebView 实例（Activity 内）
val web = ChromiumWebView(activity)  // 单 Context 参数；内部自建 WindowAndroid
setContentView(web)                    // 或 container.addView(web)
web.loadUrl("https://example.com")

// ③ 销毁（Activity.onDestroy，必调）
web.destroy()  // 否则 WebContents 泄漏

进程架构

内核启动后产生三类进程：

  • browser 进程：你的 Application 主进程，运行 ArupaKernel.initialize()。
  • privileged_process：GPU / 网络服务进程（5 个，需 Manifest 声明）。
  • sandboxed_process：renderer 沙箱进程（40 个，需 Manifest 声明）。

6. AndroidManifest 进程声明

内核子进程的 Service 类在 AAR classes.jar 中，但消费端 Manifest 必须逐字声明：40 个 sandboxed + 5 个 privileged chromium child-process service，以及 2 个 NUM_*_SERVICES meta-data。

💡 自动化工具

使用内核提供的脚本 tools/arupa-kernel-manifest-patch.py 自动向 AndroidManifest.xml 注入所有声明，无需手写 45 个 service 条目。

<!-- AndroidManifest.xml 片段示例（由工具生成，此处仅示意结构） -->
<manifest>
    <!-- NUM_*_SERVICES meta-data -->
    <meta-data android:name="org.chromium.content.browser.NUM_SANDBOXED_SERVICES"
               android:value="40" />
    <meta-data android:name="org.chromium.content.browser.NUM_PRIVILEGED_SERVICES"
               android:value="5" />

    <!-- sandboxed 子进程（0~39，service0 含 useAppZygote）-->
    <service android:name="org.chromium.content.app.SandboxedProcessService0"
             android:process=":sandboxed_process0"
             android:isolatedProcess="true"
             android:useAppZygote="true"
             android:exported="false" />
    <!-- ... service1 ~ service39 ... -->

    <!-- privileged 子进程（0~4）-->
    <service android:name="org.chromium.content.app.PrivilegedProcessService0"
             android:process=":privileged_process0"
             android:exported="false" />
    <!-- ... service1 ~ service4 ... -->
</manifest>

    override fun shouldInterceptRequest(
        url: String, method: String,
        isForMainFrame: Boolean, headers: String

            return ArupaWebResourceResponse(
                mime = "text/html",
                encoding = "utf-8",
                status = 200,
                headers = null,
                body = body
            )
        }
        return null  // 放行

// 完整 Client 回调注册示例
web.setClient(object : ChromiumWebView.Client {
    override fun onPageStarted(url: String) {
        addressBar.setLoading(url)
    }
    override fun onPageFinished(url: String) {
        addressBar.setDone(url)
    }
    override fun onLoadProgressChanged(p: Int) {
        progressBar.progress = p
    }
    override fun onReceivedTitle(t: String) {
        tab.title = t
    }
    override fun onReceivedError(u: String, code: Int) {
        showErrorPage(u, code)
    }
    override fun onRenderProcessGone() {
        // 必须处理：重建 view
        recreateWebView()
    }
    override fun onShowFullscreen() { enterImmersive() }

    }

        pickFiles(types, mode) { paths ->
            web.onFileChooserResult(id, paths)  // 取消传 null
        }
    }

        url: String, ua: String, cd: String, mime: String, len: Long

11. FB-A001：setTransportRoute 无效 / pending 兜底缺失

状态：已修复（内核侧 528d43bf）对接侧升级被 FB-A002 阻塞中

根因

ChromiumWebView(Context) 构造函数不创建 WebContents（延迟到首次导航），mWebContents 初始为 null。旧版 setTransportRoute 的 Java 字节码在 mWebContents==null 时直接 return，无 pending 兜底字段（对比 setPendingProxy 有 mPendingProxyUrl），导致调用被静默丢弃。

修复内容（AAR 528d43bf）

  • 新增 mPendingTransportEndpoint / mPendingTransportHosts 字段（对称 mPendingProxyUrl）。
  • setTransportRoute 无条件存 pending，再 if mWebContents!=null 立即 apply。
  • initFromNativeWebContents（WebContents 就绪时）自动 re-apply pending，在首次 loadUrl 前生效。

对接侧行动

  • 等 FB-A002 内核侧修复后升级到新 AAR（sha 528d43bf…）。
  • NomadBrowser 的 setTransportRoute 调用一行不用改，pending 兜底自动覆盖时序问题。
  • 可去掉 setPendingProxy 全局兜底，改回真正的 split-tunnel。

临时规避（旧 AAR 期间）

// 临时：用 setPendingProxy 全局兜底替代 setTransportRoute
// 对接侧 ChromiumProxyPrefs commit 5e054b1 已实现
web.setPendingProxy("socks5://127.0.0.1:55087")
// 升级新 AAR 后改回：
// web.setTransportRoute("socks5://127.0.0.1:55087", arrayOf("api.example.com"))

13. 其他已知限制

  • WebView 共存禁忌：in-process chromium 与系统 android.webkit.WebView 同进程 = JNI_OnLoad SIGTRAP。ENABLED 路径加载 ArupaKernelImpl 后必须 return，跳过 AOSP WebView 内核及其 eager new WebView 的 microapp/plugin 注册。
  • find 不索引合成页：loadDataWithBaseURL 内容 findAllAsync 返回 0/0。真实 HTTP/HTTPS 页正常。
  • 地理位置权限以外的其他权限默认 deny（反指纹策略）：摄像头/麦克风通过 onPermissionRequest 回调，App 自行决定 grant/deny；其余权限（传感器等）default-deny。
  • onReceivedIcon 传 URL 非 Bitmap（#233）：与 AOSP 不同，需 App 自行下载 icon。
  • 首次导航前调特权 API 须用 Pending 版本：用 setPendingProxy / setPendingIdentity，避免 WebContents 尚未创建时丢失配置。
